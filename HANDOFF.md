## 1. OBJETIVO DEL PROYECTO
PWA de consulta rapida para urgencias: cheatsheets, escalas clinicas, formulas, protocolos de codigos de activacion (IAM/ictus/trauma/sepsis/riesgo suicidio), farmacos con perfusion IV calculada por peso, checklist de intubacion/SIR, fichas tecnicas y bibliografia. "Terminado" no aplica (herramienta viva de uso clinico); cada sesion anade/corrige contenido o UI.

## 2. STACK Y ARQUITECTURA
| Capa | Tecnologia | Version | Archivo clave |
|---|---|---|---|
| Frontend | HTML/CSS/JS vanilla, sin build ni framework | - | `index.html` (2388 lineas, monolito con CSS+JS embebidos) |
| Datos | Modulos JS `window.X = [...]` cargados como `<script>` | - | `data/{cheatsheets,scales,formulas,protocols,protocols-ped,drugs,infusions,intubacion,fichas,bibliografia}.js` |
| Offline | Service Worker network-first (cache solo como respaldo sin conexion) | `CACHE = 'urg-v71'` | `sw.js` |
| PWA | Manifest | - | `manifest.json`, `icon.svg` |
| Hosting | Cloudflare Pages, deploy automatico en push a `main` | - | (integracion nativa GitHub, sin paso de build) |
| CI | **Ninguno.** No hay GitHub Actions en el repo (ver decision de sesion 4 continuacion 9) | - | - |
| Ingesta de fichas | Scripts Node puntuales (no pipeline automatizado) | - | `scripts/parse_fichas.js` (parsea `medicamentos/*.md`, extraido de PDF de Guies Cliniques catalanas), `scripts/merge_fichas.js` (75 fichas → `data/fichas.js`), `scripts/patch_fichas_verificacion.js` |

**Decisiones cerradas (no re-discutir):**
- Sin backend, sin framework, sin build: todo el frontend vive en `index.html` + `data/*.js` cargados directo por `<script>`. Confirmado sin `fetch()`, sin `<form>`, sin secretos en codigo. Excepcion PREPARADA pero NO publicada (sesion 18): rama local `ideas-ia` con una Pages Function `/api/ideas` (Claude); el usuario decidio no publicarla mientras la app sea publica (ver backlog #19).
- `localStorage` solo para `urg-favs`/`urg-recent`/`urg-theme` (favoritos, recientes, tema) — nunca dato de paciente.
- `sw.js` es **network-first** desde `urg-v64` (sesion 6): con conexion siempre sirve lo publicado (`fetch` con `cache:'no-cache'`, revalida la cache HTTP) y actualiza la copia local; la cache solo responde sin conexion. Ya **no** hace falta subir `CACHE` en cada cambio de `index.html`/`data/*.js`.
- Dosis de farmacos siempre con peso real; peso ideal solo para volumen tidal (ver memoria de usuario `peso_real_vs_ideal_dosis`).
- `data/infusions.js` es la **unica fuente de verdad** para calculo de mL/h de perfusion IV. `data/drugs.js` no debe tener su propio `doseCalc`/`extra` que calcule mL/h para un farmaco que tambien este en `INFUSIONS` — solo `infusionRef` + boton "Perfusion IV". Motivo: sesion 3 encontro 4 farmacos (noradrenalina, dopamina, dobutamina, midazolam) con dos diluciones de referencia distintas en cada archivo, hasta 6x de discrepancia en mL/h para la misma dosis prescrita.

## 8. ENTORNO Y COMANDOS
- Sin instalacion: es HTML/CSS/JS estatico, se abre `index.html` directo o se sirve con cualquier servidor estatico.
- Scripts de ingesta de fichas (uso puntual, no en cada sesion): `node scripts/parse_fichas.js` luego `node scripts/merge_fichas.js` (requieren los `scripts/fichas_es_batch*.json` y `medicamentos/*.md` presentes).
- Deploy: automatico via integracion nativa Cloudflare Pages ↔ GitHub en cada push a `main`. No hay comando manual de deploy en este repo.
- Purga de cache: **ya no existe** (workflow eliminado 2026-09-04, ver BUG-6). `_headers` mantiene `Cache-Control: public, max-age=300`, pero desde la sesion 6 el service worker pide cada recurso con `cache:'no-cache'` (revalidacion contra el servidor), asi que con la app ya instalada el contenido nuevo se ve en la siguiente carga tras el deploy. Los 5 min de `max-age` solo afectan a navegadores sin SW activo.
- No hay CI, ni GitHub Actions, ni secrets configurados en el repo.
- No hay variables de entorno locales, no hay `.env`.
- No hay comando de test ni de build.

Consecuencias que hay que respetar: (1) la trampa de Tab debe recorrer TODO el overlay, no solo `#ficha-modal`, o los campos del panel quedan inalcanzables por teclado; (2) el `onclick` de cierre del overlay usa `event.target===this`, asi que clicar el panel no lo cierra (no romper esa condicion); (3) `closeFicha()` y `openGaleria()` tienen que vaciar y ocultar el panel a mano; (4) el foco se pone con `focus({ preventScroll: true })`: sin eso, en pantalla estrecha el navegador desplaza el modal a la vista y se salta la calculadora, que va encima.
- **El overlay de fichas cambia de eje en `<=1080px`** (`flex-direction: column`), y ahi `justify-content` deja de centrar en horizontal para centrar en VERTICAL: con `center`, el contenido mas alto que la pantalla se desborda hacia arriba fuera del alcance del scroll. Por eso la media query fuerza `justify-content: flex-start` y quita el `sticky` del panel (competia con `.ficha-top`, tambien sticky en top:0 y con z-index mayor). No revertir ninguna de las dos sin volver a medir la geometria en columna.
- **Verificar layout responsive aqui exige forzar la media query, no leerla**: el entorno no redimensiona el viewport (`innerWidth` fijo en 1440 pese a `resize_window`). El metodo que funciona es bajar el umbral via CSSOM (`regla.media.mediaText`) y medir `getBoundingClientRect`; comprobar solo que la regla CSS existe da falsa confianza (asi se colaron 3 bugs en la continuacion 7).
- En la calculadora, **indicacion y via son cosas distintas**: la indicacion es el motivo clinico (sedacion, convulsiones, TVP) y la via el modo de administracion (IV, IM, SC...). Una misma indicacion puede tener dosis DIFERENTES segun la via (Ketamina: IV 0,25-0,5 vs IM/intranasal 2-4 mg/kg), por eso cada via apunta a su propia opcion parseada y el selector de via no es decorativo: cambiarlo cambia el numero.

- **Motor de escalas/formulas (`calcScale`)**: con `calcCustom`, los valores crudos se leen con `parseFloat(el.value)||0`, y un checkbox da `"on"` -> 0. Por eso las escalas con `calcCustom` usan `sel` (con `btn:true`) para los si/no, nunca `chk`. `interp(s)` solo recibe el numero: para mostrar mas datos, `calcCustom` guarda el analisis en `this._x` (se llama como metodo del objeto) e `interp` lo lee (patron de `f-gasometria`, `f-qtc`, `f-na-correccion`, `years`, `dd-edad`, `ccspine`).
